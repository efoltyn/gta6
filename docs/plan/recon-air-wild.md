## MISSION A — AVIATION NETWORK ("an airport outside every city")

### A1. What island_airport.js actually is
`/Users/elifoltyn/Downloads/gta6/src/city/island_airport.js` (2936 lines) is **one hardcoded landmass**, registered via a single `CBZ.addLandmass(function(city){...}, 21)` call at line 1313. It is **not a function you can call twice** — every coordinate in the file (runway, terminal, tower, gates, fence, causeway) is a literal offset from two module-level consts:
```
island_airport.js:1292-1299
const _WOFF = (CBZ.worldOff && CBZ.worldOff("airport")) || { dx: 0, dz: 0 };
const A_MINX = -900+_WOFF.dx, A_MAXX = 290+_WOFF.dx, A_MINZ = -280+_WOFF.dz, A_MAXZ = 40+_WOFF.dz;
const CW_MINX = -12, CW_MAXX = 12, CW_MINZ = -566, CW_MAXZ = A_MINZ;
```
`CBZ.worldOff(id)` (defined in `world/layout.js`) is a **per-named-landmass build-time reposition dial** — it moves *the one* airport to a different spot on the map (used for the stage-2/3 map enlargement), it does **not** support N independent instances of "an airport."

Anatomy, all inside that one build closure:
- **Runway** — one unified canvas-baked ground texture (island_airport.js:1395-1478) carrying grass + runway + taxiway + apron + all paint in ONE mesh (explicitly to kill z-fighting flicker between separate slabs). RWY 09/27, E-W, `RWY_X0=-850+ADX` to `RWY_X1=240+ADX` → **1,090 m long × 30 m wide** (island_airport.js:1380-1382). Runway/taxiway edge lighting is ONE `InstancedMesh` (island_airport.js:1492-1512).
- **Terminal** — `CBZ.cityMakeBuilding(...)` shell (island_airport.js:1526-1611): 4 check-in desks (solid colliders), a gate lounge of real sittable benches registered through `CBZ.propRegisterSeat` (4 draw calls total via `InstancedMesh` for cushions/backs/arms/beams).
- **Tower** — a 34 m shaft + glass cab, solid collider, beacon light (island_airport.js:1617-1634). Purely a static prop; no ATC logic reads it.
- **Gates / aircraft** — `buildAirliner()`/`buildPrivateJet()` (island_airport.js:2132-2424) build the real flyable geometry (part-kit merged to ~12 draws/plane). **4 airliner gates at fixed x = `-120+i*55+ADX`, i=0..3** (island_airport.js:2433-2436), **2 fixed private-jet spots** (2439-2440), plus **1 scripted mid-pushback airliner** (non-boardable, purely visual state machine dwell→push→taxi→hidden→dwell, island_airport.js:2448-2544) with a real drivable baggage tug (`CBZ.cityRegisterVehicle`). 2 jet-bridge stub props (2557-2562).
- **Cabin / boarding** — every airliner gets a real walk-in cabin (liner shell, real economy seats at 0.79 m pitch via the `R()`/`Rm()` real-metres solve, cockpit with 2 crewed pilot seats, a real animated cockpit door with its own collider). Boarding is the shared **"elevator-grammar" arc** in `aircraft_doors.js` (see A3) plus island_airport.js's own `cabinCompleteBoard/cabinCompleteExit/cabinZones` state machine (island_airport.js:585-1151). Player boarding hands off to `playeraircraft.js`'s `spawnFlyableFromProp()`/`enterAircraft()`, which now **ejects the crew alive** via `CBZ.cityVacateFlightDeck` (playeraircraft.js:1036-1050) before handing over the seat.
- **Keep-outs** — `CBZ.registerNoSpawnZone(city, {...})` × 2: airside (runway+taxiway+apron) and the terminal footprint (island_airport.js:2857-2860), so ambient NPC scatter never spawns on the runway.
- **Roads** — 3 `city.roads.push({...})` records: the 24 m/3-lanes-per-dir causeway (via `CBZ.buildHighway`, island_airport.js:2661-2666) plus a **landside perimeter access road** added specifically because the old layout forced cars to cross the live runway to reach the terminal kerb (island_airport.js:2910-2921, `district:"airport"`, low-weighted but open in `roadrules.js`).
- **Region registration** — 2 `CBZ.registerCityRegion(city, {...})` calls: "Halloran Field" (rect) + "Halloran Causeway" (island_airport.js:2833-2840). This is the generic contract every landmass/biome module in the game uses (see `worldmap.js` header, A4).
- **Staffing** — island_airport.js does **NOT** use the game's declarative venue-staffing kit (`citystaff.js`'s `CBZ.cityStaffVenue`/`CBZ.cityStaffPost`, see A5). It hand-rolls its own `populate()`/`airportRole()` (island_airport.js:2696-2784): 14 travellers, 6 ground crew, 4 gate agents, all placed by literal x/z math, plus a generic `CBZ.registerWorkAnchor(...)` call for ground-crew apron task points (island_airport.js:2810-2827) — that one *is* a generic, reusable, already-multi-instance-safe hook.

### A2. Other airstrips today
- **Military base** — `/Users/elifoltyn/Downloads/gta6/src/city/island_military.js` (1579 lines) has its own bare **airstrip**: 5 parked fighter jets + 1 heavy bomber (island_military.js:1212-1218), 4 helipads each with a parked helicopter (1220-1232). All boardable/stealable via the same `placeModel(..., "plane"/"heli", ...)` → `CBZ.cityRegisterMilitaryVehicle` pattern. **No terminal, no tower, no gates, no cabin, no boarding-arc choreography** — it's a runway + parked hardware, not an "airport." Perimeter fence is `H=2.4` colliders (island_military.js:858-931), same height as the airport's.
- **Minicities** (`minicities.js`) — 4 templated satellite towns (goldspire/capeharbor/neonreef/foundry) — **none has an airstrip of any kind today**.
- **Nations** (`countries.js`) — 4 nations (Veridia, Kesh, Solara, Mbeya), 10 named settlements total (4 capitals + 6 towns/villages, countries.js:188-303) — **no airstrips**.
- So today there are exactly **2** flyable-aircraft sites in the whole game: Halloran Field (full airport) and the military base (bare airstrip). Everywhere else, "every city" has no way to fly in or out.

### A3. Ambient sky vs. real flyable aircraft
- **Ambient fleet** — `city/airtraffic.js` (1014 lines): `N_TRAFFIC = 4` deterministic (position-hash, never `Math.random`) GA prop planes + light helis, flown on **stacked circular orbit bands around the mainland city** (airtraffic.js:80-100ish), banking at physically-correct turn radius. **Cannot be boarded, carries no cargo/passengers, takes no part in the wanted system.** `AIR_TRAFFIC_COLLIDE` (default on) kills a craft that flies into a building the same way a shot-down craft dies (airtraffic.js:335-520, the ring-scan collider-strike system). This is pure atmosphere circling ONE point — not point-to-point transit between named places.
- **Police jet** — `city/aircraft.js:1898-2003` — a full authored **phase state machine**: `spool→taxi→lineup→takeoff→inbound→attack→egress→return→landing→taxiHome`, single airbase, combat-only target-seek. This is the closest existing "departure/arrival choreography" pattern in the codebase (a jet that taxis, takes off, transits, and lands again on a schedule-like trigger) — but it's single-base and player-hostile, not reusable as-is for a civil shuttle.
- **Player flight start hook** — `CBZ.cityAirborneStart` (`playeraircraft.js:1072-1103`) drops the player into a chosen parked aircraft already airborne at a given alt/heading/speed — used exactly once, by a mission opening (`city/origins.js:1375-1429`, a "cold open at 1,750 m" cinematic). **This is not an autopilot** — after the hand-off, flight is 100% manual player control. There is no AI-flown route, no waypoint list, no flight plan anywhere in the codebase.
- **Closest thing to a "route leg"** — `games/airport.js` (916 lines), the Redeye International charter-pilot minigame layered on top of the one real airport. Its `DESTS` table (games/airport.js:147-158) is **3 abstract open-water "sea anchors"** (a lit beacon + proximity/altitude delivery trigger) — explicitly **not real landmasses**: the file's own comment calls them "uncontrolled outstations." You always fly out to one, then fly back and land on the **same single Halloran runway 27**. This proves the "fly somewhere and come back" loop, PAPI/glideslope grading, and real-touchdown-physics scoring already exist and work — but there is no second landable airport anywhere to land the loop *at*.

### A4. The landmass-module contract (how a builder plugs into the world)
`world/worldmap.js` header (lines 1-29) documents the contract every island/biome file follows:
```
CBZ.addLandmass(function (city) {
   ...build meshes onto city.root...
   CBZ.registerCityRegion(city, { name, biome, kind:'circle'|'rect', ... });
}, order);   // lower order builds first
```
`world.js` runs every registered builder once per world build. This is generic and multi-instance-safe **in principle** — nothing stops N calls to `CBZ.addLandmass` — but `island_airport.js` itself is written as a single closure over fixed constants, not a `function(city, place){...}` taking a placement record.

### A5. What's already venue-kit-shaped (the reusable pieces for stamping N airports)
Two existing systems are the exact shape "N airports" needs, and neither is used by island_airport.js today:

1. **`minicities.js` — the stamping pattern itself.** Lines 60-67 define a `PLACEMENTS` array (`[{id, ax, az, cx, cz, hx, hz, road}]`), and `buildMiniCity(city, place)` (minicities.js:154-247) reads ONE entry + a template recipe (`CBZ.CITY_TEMPLATES`, `citytemplates.js`) and produces: ground pad → `CBZ.buildTown(...)` → `CBZ.registerCityRegion` → an auto-derived causeway/road link toward the nearest existing road (`CBZ.roadClamp`-checked) → `CBZ.registerWorkAnchor` for jobs. The whole PLACEMENTS array is walked in one `CBZ.addLandmass(fn, 34)` with **each entry independently try/caught** (minicities.js:262-267) so one bad stamp can't sink the world. **This is the proven template for "N of a templated venue from a data table."** Turning island_airport.js into `buildAirport(city, place)` fed by a similar `AIRPORT_PLACEMENTS` array (one entry per named settlement — mainland, 4 minicities, 4 biome towns, up to 10 nation settlements ≈ high teens of candidate sites) is the direct analog.
2. **`CBZ.venueSite` — the perimeter/gatehouse/sign/lamp/parking kit.** Defined in `speedway_structures.js:1386-1389` = `{ fence, gatehouse, monument, lampRow, bays, census, sites }`, already used by `island_speedway.js` and `arena_fights.js`. Draw-call disciplined by design (fence = 2 draws for *any* length, gatehouse ≈16, lamp row = 4, monument = 3, `bays()` derives painted stalls and parked-car slots from ONE layout so they can't disagree). **island_airport.js hand-rolls its own fence/tower instead of using this kit** — adopting `venueSite.fence`/`gatehouse` for a smaller "regional airport" perimeter + checkpoint would be far cheaper per instance than re-authoring island_airport.js's bespoke fence code N times.
3. **`citystaff.js` — declarative venue staffing.** `CBZ.cityStaffVenue(id, {stations, census})` declares job posts as DATA at build time; a body is minted only within 170 m and released past 320 m (CLAUDE.md's own note on this, math cited there). Used by casino/beach/marina/govcomplex/fishing/etc. **island_airport.js's `populate()`/`airportRole()` is a parallel, bespoke implementation that does not go through this kit** — for N airports to staff themselves without N copies of hand-placed x/z desk coordinates, this is the adoption that would pay off.
4. **`CBZ.registerWorkAnchor`, `CBZ.registerNoSpawnZone`, `CBZ.registerCityRegion`, `city.roads.push` records** — all already generic, coordinate-parametric, and safe to call N times (island_airport.js already calls them this way for its one instance).

### A6. Concrete gap list for "N airports + airliners flying between cities"
- **No multi-airport registry.** Nothing enumerates "the airports in this world" — a second `island_airport`-shaped builder would need to register itself into some new `CBZ.airports` list for a future AI-airliner system to read origin/destination pairs from.
- **No route/flight-plan/waypoint system for AI aircraft.** Every existing "AI plane" (ambient traffic, police jet) flies a fully authored, hand-tuned local track; there is no generic "fly from A to B along N waypoints, land, taxi, dwell, depart" driver. The police jet's phase machine (A3) is the nearest reusable skeleton, but its taxi/lineup/takeoff/landing math is all measured relative to ONE hardcoded home base (`j.home`), not general.
- **No passenger/cargo meaning for an airliner "flight."** Cabin seats today only ever hold parked, non-moving passengers (npc life casts them once); there's no concept of a manifest that travels with a flight or unloads at a different airport.
- **The one working "fly out and back" loop (`games/airport.js`) deliberately avoids landing anywhere real** — its own header explains why (abstract sea anchors, not a second landmass) — so it is not a precedent for "land at Airport B," only for "fly a real distance and get graded on the return landing."

## MISSION B — FAUNA SCALE ("way more animals, especially sea animals")

### B1. The population model: one flat world-wide budget, no per-species caps
`city/wildlife.js` (2999 lines) is explicit that there is **no population budget by design** (header, wildlife.js:28-32): "there is NO population budget. Species spawn their natural populations; the ONE quality knob... governs cost via a per-tier LOD visibility radius." The actual numbers:
```
wildlife.js:76        ANIMAL_VIS = [90, 130, 190, 270, 360]   // LOD visibility radius per quality tier 0..4
wildlife.js:77-79     AQUATIC_R0=560, AQUATIC_R1=1500 (sample band), FIELD_CX=0, FIELD_CZ=-700
wildlife.js:818       DENSITY = 850          // TOTAL individuals, WHOLE MAP, all biomes + ocean combined
wildlife.js:819       BIOME_SHARE = { forest:.25, farmland:.16, desert:.23, snow:.16, water:.20 }
wildlife.js:820       RARITY_WEIGHT = { common:12, uncommon:4, rare:1 }
wildlife.js:821       PRED_MAX = 0.20        // predators capped at 20% of a biome's target
```
`planBiome()` (wildlife.js:837-866) turns a biome's `target = round(DENSITY*BIOME_SHARE[biome])` into per-species integer counts by rarity weight, redistributing any predator overshoot to prey, with a hard **minimum of 1 individual per defined species** (presence is not optional) — largest-remainder rounding keeps the biome total exact. Legendaries (wildlife.js:878-886) are always **exactly 1 individual, world-wide**, never bred (`respawn:false`).

**Breeding is population-relative, not a respawner** (wildlife.js:889-964): a species' own currently-seeded population is its own carrying-capacity ceiling (`CAPS{}`, recorded once at spawn); a hunted-to-zero species is **extinct forever**. This means bumping `DENSITY` is the *only* lever that raises both the starting population **and** the ceiling the ecosystem can ever breed back up to.

### B2. The aquatic slice, concretely
5 of 45 total species are aquatic (`wildlife/aquatic.js`, 227 lines — Mackerel/common, Great White Shark/rare, Humpback Whale/rare, Dolphin/common, Megalodon/legendary), i.e. **11% of the bestiary** gets **20% of the population budget** — generous per-species, but the absolute number is small because the ocean is enormous. Back-of-envelope from the constants above (`wSum` over common=12+12, rare=1+1 → target≈170, `PRED_MAX` never triggers since shark alone is well under the 20% cap): **≈78 mackerel, ≈78 dolphins, ≈7 great whites, ≈7 whales, 1 megalodon ≈ 171 sea creatures total, for the entire ocean.** Full species count/roster: `wildlife_species.js` (1, the reference deer) + `wildlife/aquatic.js`(5) + `bears.js`(4) + `bigcats.js`(5) + `canines.js`(4) + `farm.js`(6) + `forest_deer.js`(4) + `megafauna.js`(4) + `small_game.js`(3) + `snakes.js`(5) + `snow_ungulates.js`(4) = **45 species**, matching CLAUDE.md's own "all 45 species" note.

**Geographic confinement risk (worth auditing before just raising DENSITY):** `oceanPoint()` (wildlife.js:186-204) and `waterfield.js`'s `randomWaterPoint()` (waterfield.js:247-291) sample their PRIMARY 96 tries inside a **fixed annulus** `r0=560..r1=1500` around a **static** `FIELD_CX,FIELD_CZ=(0,-700)` — i.e. centred on the ORIGINAL mainland, predating `world/layout.js`'s stage-2/3 map enlargement that pushed the 4 nations + the snow island out to rings of ~1300-2200+ units. There IS a self-healing fallback to `CBZ.SEA_WORLD_BOUNDS` (the real full sea footprint) once the 96 tries fail — and the code comment for that fallback literally says "the continent expansion can consume an old radial ocean band entirely," proving this exact class of bug already bit the project once — but since the fixed band still finds valid deep water near the (populous) mainland almost every time, **most aquatic spawns likely still cluster near the original mainland coast rather than spreading proportionally out to the enlarged map's outer-ring coastlines.** Worth confirming with `tools/terrain-map-audit.mjs` or a live census before assuming "more DENSITY" alone fixes "more sea animals everywhere."

**No schooling-fish/InstancedMesh system exists.** Despite `wildlife/aquatic.js`'s mackerel being defined with `herd:[10,20], packs:4` (i.e., the game already intends visible schools), each individual fish is built exactly like every other animal (see B3) — there is no shared instanced "school" renderer, no flocking/boid behavior beyond the same herd-centroid system land animals use (`joinHerd`/`updateHerds`, wildlife.js:733-757).

### B3. Per-animal cost: draw calls are the real ceiling, not the AI tick
- **Every animal is a hand-authored `THREE.Group` of individual Box/Cone meshes**, built once by the species' `build(ctx)` function (`wildlife_species.js` schema doc, lines 1-33) and added directly to the scene root (`makeActor()`, wildlife.js:212-269). **Nothing is merged via `BufferGeometryUtils` and nothing is instanced** — a deer is ~15 separate meshes, a mackerel ~11, a whale/elephant more. This is the exact opposite of every other repeated-object system in this codebase: fence posts, lamp rows, gate-lounge benches, parking bays all go through `InstancedMesh`/BGU-merge to 1-4 draw calls regardless of count (see `CBZ.venueSite`, A5). **Animal draw calls scale linearly and directly with visible animal count** — this is the single biggest cost driver for "5-10x more animals," especially for schooling fish, which by nature cluster densely in view together (a visible school of 15 mackerel today ≈ 165 draw calls).
- **The per-frame walk is O(`animals.length`) every frame, unconditionally** (`tick()`, wildlife.js:2499-2517), but the work INSIDE that loop is aggressively gated: far + calm land animals literally `continue` after one `turnT -= dt` (wildlife.js:2674-2696, "FAR + CALM land animals FREEZE"), with three deliberate exemptions that keep simulating off-screen: a feeding animal, a hungry unsated predator within `HUNT_SIM_R`, and anything in a hot state (flee/charge/stalk) — "so a shot herd genuinely LEAVES instead of pausing at the horizon." **Aquatic apex predators are the one aquatic case that never freezes off-screen at all**: sharks/megalodon run `CBZ.sharkBrain` even while hidden (wildlife.js:2591-2603) because the fin-proxy horror design (`wildlife_shark.js`) depends on the shark actually closing distance unseen — so shark-class predators are the most expensive aquatic individual to multiply.
- **Predator/food-chain cost is centralized but not free.** `systems/predator.js` (3084 lines) is explicitly the fix for a documented anti-pattern — its own header quotes the repo's ratchet: **"18-25 independent AI update loops (only 2 share code)"** — and consolidates the stalk/seize/dread-audio state machine so land predators and (via a locomotion-callback seam) sharks share one driver instead of each inventing its own. `wildlife_shark.js` (524 lines) contributes only numbers + a locomotion seam + the fin/wake/shadow render proxy — explicitly NOT a second AI loop, by design, to avoid re-fragmenting this. Per-animal, the real cost is a handful of still-separate state machines that all run inside `wildlife.js`'s own `tick()`: `venomTick`, `updateHerds`, `feedTick`, `huntTick`, `snakeTick`, gait/swim animation — each cheap alone, additive per active (non-frozen) animal.
- **`breed()`** (wildlife.js:916-964) runs every `BREED_EVERY=26s`, bucketing all LIVE animals by species — O(animals), but infrequent, so it scales fine even at 5-10x.

### B4. What 5-10x animal counts would actually need
1. **Instancing/merging tier for common, clustering species first** — mackerel/dolphin schools and any "herd standing together in view" are the highest-leverage target: convert to a true `InstancedMesh`-driven school (shared geometry/material, per-instance transform only) the same way `venueSite.fence`/lamp rows/gate benches already do elsewhere in this codebase. This is the single change that decouples "more individuals" from "more draw calls."
2. **A real 2-tier LOD, not today's binary visible/frozen switch.** `wildlife_shark.js`'s fin+wake+shadow proxy (524 lines, "the fin is the point") is already a proven pattern for representing a whole detailed body cheaply at distance/most-of-the-time — the same trick (a cheap billboard/silhouette/instanced-proxy standing in for the full mesh beyond some radius) generalized to schooling fish and to large megafauna would give a genuine far-tier body instead of just hiding the full mesh.
3. **Re-audit `AQUATIC_R0/R1`/`FIELD_CX/CZ` against the post-`world/layout.js` map size** (B2) before assuming raw `DENSITY` scaling reaches the new coastline near the nations/snow ring.
4. **Raising `DENSITY` (850 → ~4250-8500) alone is cheap for the frozen-loop walk and for `breed()`**, both already amortized/gated — the real, non-automatic costs it raises are: scene-graph mesh count + shadow casters (`castShadow=true` per mesh, `makeActor()` wildlife.js:227) and, in any crowded view, draw calls (B3) — which is exactly why (1)/(2) need to land alongside any DENSITY increase, not after it.

## MANTLE / CLIMB QUESTION

### Player collision model (`systems/physics.js`, 904 lines)
- **Not a true 3D capsule.** The player is a horizontal **circle** (`player.radius`) resolved against each AABB collider by shortest-push-out (`collide()`, physics.js:124-157); a collider is only height-relevant through an explicit, optional `c.y0/c.y1` band tested against `feetY/headY` (a window sill, a half-wall) — there are no rounded vertical caps, no true capsule math. `collideSlide()` (physics.js:176-188) is the convergent multi-pass version used by NPC movers.
- **`STEP_UP = 0.45 m`** (physics.js:18) — the player auto-climbs a riser/curb/sill up to 0.45 m, tuned down from an old 0.9 specifically because 0.9 "over-climbed... nearly a whole flight in one frame." `STEP_DOWN = 0.9 m`, `SNAP_DOWN = 0.35 m` glue the feet to a slightly-lower surface to prevent bounce.
- **`STEP_UP_NPC = 0.9 m`, city-mode-only, NPC-only** (`npcStepLedge()`, physics.js:210-237) — a bounded auto-step onto a low ledge (window sill, planter) **only when the body is actually moving toward it** (a dot-product gate against the move vector). This is architecturally the closest existing thing to "detect a low grabbable ledge ahead," but: never runs for the player, caps at 0.9 m, and is an instant Y snap, not an animated climb.
- **Jump is a single fixed impulse** (`player.vy = T.jumpVel`, physics.js ~806) with ordinary gravity integration afterward. **No double-jump, no wall-jump, no air-borne ledge-grab raycast, no "hang" state** anywhere in the player controller.
- **No climb/vault/parkour system exists anywhere in the repo.** A repo-wide grep for climb/vault/mantle/parkour/ledge across `src/systems` and `src/city` turns up only: `npcStepLedge` (above), the building-stair **continuous ramp** platform system (`groundAt()`/`CBZ.platforms`, physics.js:239-350 — walkable surfaces above terrain, but only reachable within `STEP_UP` of current feet, i.e. still just stair-walking), and `elevators.js`'s scripted ride (a different, non-jump grammar). None is a jump-triggered grab-and-pull-up.

### Fence heights around the military base
Both the airport's and the military base's perimeter fences are **2.4 m solid colliders**:
- `island_airport.js:2569-2570` — `const T = 0.4, H = 2.4` (perimeter fence, chain-link `InstancedMesh` posts + one merged panel mesh, y-gated 0..2.4).
- `island_military.js:900-912` — every `col(...)` call for the base perimeter is `col(x, z, w, d, 0, 2.4)`, same 2.4 m height, chain-link `InstancedMesh` posts (`island_military.js:858-931`).

2.4 m is well beyond both `STEP_UP` (0.45 m) and `STEP_UP_NPC` (0.9 m) — today these fences are simply flat walls, passable only through the vehicle gate / pedestrian water-access gaps authored into each perimeter. There is nothing partially climbable about them today.

### What a mantle (jump → grab-top → jump-again) would hook into
No ready-made system exists, but three already-proven patterns are the right shape to reuse:
1. **`aircraft_doors.js`'s "arc" pattern** (`begin()`/`guide()`/`endArc()`, aircraft_doors.js:192-318) — a scripted, cancellable, input-overriding player-position tween with a clean success/fail/cancel contract (dies cleanly on player death, mode change, or the target becoming invalid). A mantle's "detect grabbable ledge → play climb tween → hand control back standing on top" beat is structurally identical to this arc's "walk to door → door opens → step through → hand control to the flight controller."
2. **`grapple.js`'s brace/hang pose discipline** (`systems/grapple.js:235-259`, survival-mode only today) — the established pattern in this codebase for writing an ABSOLUTE (not additive) pose to the rig during a scripted physical action specifically so `animChar` can't fight it frame-to-frame. A climb pose needs the same absolute-write discipline.
3. **`groundAt()`/`CBZ.platforms`** (physics.js:239-350) — the existing "standable surface above terrain, reached only within `STEP_UP` of current feet, bucketed grid query" system. A mantle's "can I actually stand up here" test is a natural extension: probe for a collider whose top sits within jump-apex-plus-reach of the player and whose top is otherwise unreachable by ordinary `STEP_UP`, then hand off to the SAME platform-standing mechanism once the climb tween completes — no new "standing" system needed, only a new way to arrive at one.

Sizing note: a mantle built to clear a ~2.4 m obstacle (fence-height + a bit of margin) is exactly what would let a player scale both the airport's and the military base's perimeter fences without touching either fence's collider geometry at all — the fences are already the right height/shape for a "jump, catch the top rail, pull up" beat; only the traversal STATE is missing.

## SHORTEST-PATH SEAMS (summary)

1. **N airports as venue stamps.** Copy `minicities.js`'s proven shape (A5.1): turn `island_airport.js`'s single build closure into `buildAirport(city, place)` fed by an `AIRPORT_PLACEMENTS` data table (candidates: mainland + 4 minicities + biome towns + nation capitals, ~high-teens sites), each entry try/caught independently exactly as `minicities.js:262-267` does. Shrink the per-instance footprint by routing the perimeter/checkpoint through `CBZ.venueSite.fence/gatehouse` (A5.2) instead of hand-rolled fence code, and route staffing through `citystaff.js`'s declarative `CBZ.cityStaffVenue` (A5.3) instead of `populate()`/`airportRole()`'s literal x/z placement — both already scale to N call sites for free. Keep one full "hero" Halloran Field; smaller stamps can be a runway+apron+small terminal without the full cabin-interior/boarding-arc machinery.
2. **Airliner city-to-city loops.** No AI route/flight-plan system exists at all today (A6) — this is new work, not an adoption. The nearest skeletons to generalize: the police jet's `phase` state machine (`aircraft.js:1898-2003`, taxi→lineup→takeoff→transit→landing→taxi-in, currently hardcoded to one base) for the departure/arrival choreography, and `games/airport.js`'s `DESTS` abstract-anchor pattern (A3) for "fly a real distance, get graded on arrival" — but that pattern must finally point at a REAL second airport (from seam 1) instead of an open-water beacon for it to become a real inter-city route. A minimal v1: reuse the jet's phase machine per registered airport pair, with `cityAirborneStart`-style state writes for the cruise leg and `aircraft_doors.js`'s arc for the gate arrival.
3. **10x fauna with LOD tiers.** Two independent levers, both additive to the existing design: (a) raise `DENSITY` (wildlife.js:818) and re-derive `BIOME_SHARE`/re-audit `AQUATIC_R0/R1` against the enlarged map (B2/B4.3) — cheap, since the frozen-loop walk and `breed()` are already gated/infrequent; (b) before or alongside that, give schooling/clustering species (mackerel first) a true `InstancedMesh` school renderer and give large/common species a cheap far-tier proxy modeled on `wildlife_shark.js`'s fin/wake/shadow trick (B4.1-2) — this is the part that actually controls draw calls, which is the real ceiling, not the AI tick.
4. **The mantle grab.** New system, but small: a jump-triggered forward probe (reuse the collider-grid query pattern already in physics.js) that finds a collider top within reach-above-jump-apex, drives a scripted absolute-pose climb tween (reuse `aircraft_doors.js`'s arc contract + `grapple.js`'s absolute-pose-write discipline), and on completion hands the player off to the existing `groundAt()`/`CBZ.platforms` standing mechanism. Target height ~2.4 m to match both the airport's and the military base's real perimeter fences (already-existing colliders, zero geometry changes needed).
